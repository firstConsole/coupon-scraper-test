# Coupon Scraper

Сбор структурированных данных и снимков карточек с сайтов-агрегаторов купонов и гифт-карт: мерчант, номинал, условия, промокод - и снимок самой карточки как подтверждение на дату.

## Стек

| Слой | Что используется | Почему |
|---|---|---|
| Язык | Python 3.13, asyncio | нагрузка целиком I/O-bound |
| Интерфейс управления | FastAPI + uvicorn | схема из типов, та же pydantic, что и в данных |
| Браузерный API | Playwright | код сбора пишется против него, браузер остаётся параметром |
| Браузер | Camoufox для цели, штатный Chromium для отладки и CI | спуфинг на уровне движка, а не патчей в JS |
| Данные | PostgreSQL 18 | состояние прогонов, очередь задач, офферы и их история |
| Координация | Redis 8 | бюджеты выходных адресов, карантины, предохранитель |
| Снимки | S3-совместимое хранилище, локально MinIO | приватный бакет, подписанные ссылки |
| Логи и метрики | structlog, Prometheus | вырезание секретов и метрики стадий сбора |

## Быстрый старт

Нужны Python 3.13, [Poetry](https://python-poetry.org/) 2.x и Docker.

```bash
make install     # зависимости и git-хуки
make env         # создаст .env из .env.example
```

Дальше откройте `.env` и заполните значения, помеченные как обязательные. Минимум, без которого проект не поднимется:

| Переменная | Где взять |
|---|---|
| `POSTGRES__PASSWORD`, `REDIS__PASSWORD` | придумайте: `openssl rand -hex 24` |
| `STORAGE__BUCKET`, `STORAGE__ACCESS_KEY_ID`, `STORAGE__SECRET_ACCESS_KEY` | для стенда — любые непустые, MinIO примет их как свои |
| `SECURITY__SECRETS_ENCRYPTION_KEY` | `openssl rand -base64 48`, минимум 32 байта |

```bash
make up          # Postgres, Redis и MinIO; команда ждёт, пока все станут healthy
make check       # линтер, типы, тесты — ровно то, что гоняет CI
```

Приложение на время разработки запускается на хосте, а не в compose - так работают отладчик и автоперезапуск:

```bash
poetry run python -m coupon_scraper api      # http://127.0.0.1:8000/healthz/ready
poetry run python -m coupon_scraper worker
poetry run python -m coupon_scraper planner
```

Порты стенда разведены с обычными (Postgres 5442, Redis 6389, MinIO 9010), чтобы он не спорил с другими проектами на той же машине.

## Команды

`make` без аргументов покажет список. Самое ходовое:

| Команда | Что делает |
|---|---|
| `make check` | линтер, типы и тесты |
| `make format` | отформатировать и починить, что чинится само |
| `make up` / `make down` | поднять и остановить стенд |
| `make destroy` | остановить и стереть данные — когда нужен чистый старт |
| `make build` | собрать рабочий образ |

Перед коммитом отрабатывают быстрые проверки, перед `git push` — `mypy` и тесты. Хуки ставятся командой `make install`.

Четыре теста поднимают настоящий браузер: без него они пропускаются, с ним проверяют, что адаптер действительно работает.

```bash
poetry run playwright install chromium
```

## Структура

Проект разложен по Clean Architecture. Стрелки зависимостей смотрят только внутрь, и за этим следит тест, он запрещает домену и приложению импортировать Playwright, SQLAlchemy, Redis и остальные восемнадцать библиотек поимённо.

```
src/coupon_scraper/
├── domain/          правила сбора: бюджет адреса, канонизация, состояния задачи
├── application/     порты во внешний мир и сценарии, включая основной цикл страницы
├── infrastructure/  реализации портов: браузер, база, хранилище, логи
├── presentation/    точки входа: api, worker, planner
└── bootstrap/       composition root: конфигурация и сборка зависимостей
```
